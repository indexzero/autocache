## [Unreleased]

### 🆕 Added
- **Capture lists in the ledger**: a ledger now holds `captures.jsonl` files beside `wayback.json` manifests. A capture list is JSONL, one capture per row, named by its replay URL (`wayback`), with an optional fetch-order `rank`. It carries no rewrite program, so it can hold every version of one URL. `discover` finds both kinds, `against` joins both, and `captures(discovered)` returns every referenced capture with the files that name it. `waybackify ledger <dir> --captures` prints that view. `ledger --flatten` is unchanged: it is the union manifest and keeps one capture per URL.
- **`@autocache/waybackify-site` and `waybackify site`**: a new package for the whole-site source. `site enumerate <config.json> --ledger <dir>` walks the CDX index for every query in a site config and writes one capture list per site, with one row per distinct version of every URL, plus the raw CDX pages, the resolved redirects, and an inventory of every CDX row. It is deterministic, and `--offline` rebuilds the ledger from the saved pages. `site export <dir> --root <root> --out <dir>` copies a cache root's bodies to `<host>/<timestamp>/<path>` with an index, and records every path it adjusts for a case-insensitive filesystem. See `docs/SITE.md`.
- **`cdx.js`: paged CDX enumeration**: `cdxPages` runs a `host`, `domain`, `prefix`, or `exact` query page by page. Every request carries a `limit`, pages chain through the resume key, and an outage (a non-200, or an HTML body under a 200) is retried from 30 s up to 10 min before `CdxUnavailableError`. `waybackify search <url> --match <type> [--from <ts>] [--to <ts>]` exposes it. An outage there exits 1 and is never an empty result.
- **`cache fill --converge`**: repeats passes until one fetches nothing and defers nothing. It backs off after a stopped or no-progress pass (`--backoff-s`, `--backoff-max-s`) and gives up after `--max-stall` passes without progress. The loop is `backfill.js#converge`.
- **`cache fill --no-requisites` and `--request-delay-ms`**: the first stores only the named captures and still records their requisite edges. The second paces the requisite requests inside one capture.
- **`cache remediate`**: the wrapper-stub remediation sweep. It refetches each `wrapper-stub` or `extension-mismatch` sidecar in a root with `id_` and recommits it. It needs no ledger. The engine is `remediate.js`.
- **`cache status <dir> --root <root>`**: a summary of a root against a ledger: the state histogram overall and per top-level ledger directory, unfetched split into gone and pending, the captures no further pass will fix with their remedy, and the store's footprint. Exit 1 while anything is pending or needs attention. The engine is `status.js`.

### 🚧 Changed
- **`cache fill` fetches pages before content**: the worklist now orders every capture named by a flagless replay URL ahead of every capture named with a replay flag (`id_`, `im_`, `oe_`), then by rank and key as before. `--pages-only` attempts the pages and leaves the content pending. The archive blocks by request form, so the forms a browser never sends go last. A worklist built before this change keeps its old order until the ledger changes or `--refresh` rebuilds it.
- **`cache fill --converge` gives up on a lasting throttle**: a throttle stop that fetched nothing counts toward `--max-stall`. An outage does not.
- **The `cache fill` worklist is bound to its ledger**: `<root>/.refetch/worklist.ledger.json` records a fingerprint of the ledger that built the worklist. A run whose ledger has a different fingerprint rebuilds the worklist. So does a run that finds a worklist with no stamp, which means the first run after this change re-enumerates once. `--refresh` still forces a rebuild.
- **`cache fill` stops on a throttle**: six captures in a row that defer with nothing fetched stop the run with `"reason": "throttled"` and exit 1, where the run used to defer through the rest of the worklist. `--throttle-after <n>` sets the count and `0` restores the old behavior. A stopped run writes `<root>/.refetch/cursor.json`, and the next run starts after the capture it stopped on. The summary line of a stopped run carries `reason` (`unreachable` or `throttled`).
- **The `cache fill` worklist orders by rank, then key**: a capture a manifest names has rank 0, so a ledger of manifests keeps its order.
- **A document fetched raw records `flag: "id_"`**: `cacheCapture` stamps the sidecar of a document named with the `id_` replay flag. Before, every named document recorded `null`. Sidecars already on disk are not rewritten.

### 🐛 Fixed
- **A changed ledger no longer leaves captures unfetched**: the worklist was built once per root and reused whatever ledger the next run named, so captures added to a ledger were skipped until `--refresh`. The stamp above closes it.
- **`docs/CACHE.md` agrees with `cache verify` about the root**: the root contract names `.refetch/`, `.crawl/`, `.verify/`, and `remaster.build.json` as the sanctioned command state that `fsck` already allowed.

## [0.5.0] - 2026-10-19

### 💥 Breaking
- **`remaster verify` reads sidecar v3 only**: the tree reader rejects a v1, v2, or unknown sidecar with `unsupported sidecar version N`. No reader or fallback exists for an older shape. Rebuild a remastered tree from a current store before you verify it. (#12)
- **The manifest reader accepts version 2 only**: `readManifest` and `validateManifest` reject a version 1 manifest with `invalid manifest — unsupported version 1 (supported: 2)`. Every entry needs a non-null `wayback` URL, and a reader never converts a `wayback: null` entry into an exclusion. Rewrite such a file as version 2 with the URL under `exclude`. The `SUPPORTED_MANIFEST_VERSIONS` export is gone. (#14)
- **The sidecar readers accept version 3 only**: every reader rejects a version 1 or 2 sidecar with `unsupported sidecar version 1 at <path>`. The prefix names the reader (`readSidecar:`, `remaster:`, `remaster verify:`, `FsStore:`, `corpus:`, `enumerateHtmlDocKeys:`, `parity:`). The `bucket verify` verifier (`parity:`) rejects at enumeration, before any bucket read. No tool upgrades an older sidecar, and the `SUPPORTED_SIDECAR_VERSIONS` export is gone. Rebuild an older root with `cache add` or `cache fill`, because bodies moved to `cap/<dd>/<digest>`. A root written before this change with version 3 sidecars needs the same refetch: its bodies sit under the capture-key hash, where no reader looks. `FsStore.get` and `remaster` fail on such a root with an error that names the sidecar and the expected body path. `bucket push` skips the entry, reports it in the summary, and exits 1 after the rest of the batch. (#15, #16)
- **`@autocache/waybackify-serve` no longer exports `./parity` and `./retry`**: the verifier and its retrying dispatcher left the serving core, and an import of either subpath now fails with `ERR_PACKAGE_PATH_NOT_EXPORTED`. Import `@autocache/waybackify-verify` and `@autocache/waybackify-verify/retry` instead. (#16)

### 🆕 Added
- **GitHub repo-root probe before a deep-link 404 counts as gone**: `backfill` and `generate` probe the repo root of a `github.com` deep link that the archive lacks. A renamed repo becomes a rewrite candidate (`.refetch/renamed.jsonl`, `manifest.rewrites`), and a default port (`github.com:80`) still matches. An inconclusive reply defers the link instead of writing a terminal record. Inconclusive replies are a 403, 408, 429, or 5xx, a redirect off GitHub or without a Location, and a network error. (#13)
- **`noRewrite` in the manifest**: an optional list of URLs the author never wants rewritten. `apply` leaves a listed URL as written and never warns, ahead of `exclude`, `rewrites`, and `entries`. `generate` skips a listed URL (no universe bake, no seen verdict, no archive call) and copies the whole set into the new manifest. The `manifest` command carries the set forward from the previous file at `-o`. Every section matches with the same key, which folds the scheme, a trailing slash, and a default port. (#14)
- **Per-FQDN behaviors in the universe**: an optional `fqdns` map, for example `"github.com": { "on404": "probe-repo-root-follow-rename" }`. Keys are bare lowercase FQDNs, and behavior names and values come from the closed `FQDN_BEHAVIORS` table, so a typo fails validation. `fqdnBehavior(universe, url)` looks up the exact host, and `subset` never bakes `fqdns` into a manifest. (#14)
- **Resumable `bucket verify`**: a run stores its progress in `<root>/.verify/`, removes it when it passes, and `--resume` skips the layers and bodies that verified. A failed layer saves its in-flight reads before it rejects, and a heal rate over 1% reports `PASS-DEGRADED` with exit 0. (#16)
- **`@autocache/waybackify-verify`**: a new package for the four-layer bucket verifier, its retrying undici dispatcher, and its checkpoint store. It depends on `@autocache/waybackify-serve` and backs `waybackify bucket verify`. (#16)

### 🚧 Changed
- **Help and report text names this repository's layout**: the `waybackify` root help summary and description say "over the waybackify library". The serve `--split` usage line and the `interstitialAsBody` finding label each drop a tracker number. (#17)
- **`remaster verify` reports upstream URLs by class**: the static escape layer lists every distinct upstream URL instead of a byte count. Each entry carries the store key it resolves to, a class, a document count, and the next command. A rewriter miss (`inStore`), a fetchable gap (`inRecordedFrontier`, `novelResource`), a `bare` reference, or an `unresolved` original fails the layer. The gate loosens for two classes. An out-of-scope page link (`novelPage`) now advises, and the layer excludes a beacon or pseudo URL (`unmirrorable`). The old scan failed both. Keys follow the store's keying. Markup and attribute values decode `&amp;`, raw text (`<script>`, `<style>`, `<xmp>`, comments) keeps it, and the `#fragment` drops from every compared key. An HTML tokenizer (`parse5`) supplies the tag names, attribute spans, and content states. Only a navigational position is a page link: `<a href>`, `<area href>`, `<form action>`, or a `<link>` whose every `rel` token is `next`, `prev`, `canonical`, or `alternate`. Every other URL position, CSS `url()` included, is a resource whatever its extension. The `--json` report adds a `residual` object with the full classified list. (#12)
- **Content-addressed body store**: a body now lives at `cap/<dd>/<digest>`, the SHA-256 hex of its bytes, and the sidecar names it through `contentHash`. Byte-identical captures share one file, and each keeps its own sidecar. `cache verify --fix` quarantines an orphan only when every sidecar proves its ownership. The proof: the sidecar parses, carries a known status, and names a body whose bytes match `contentHash` and whose size equals `contentLength`. An unparseable sidecar or an unknown status is `malformed`, a digest with no file is `missingBody`, and a wrong size is the new `sizeMismatch`. Any of them, or `hashMismatch` or `schemaVersion`, suspends the moves for the run. (#15)
- **`cache verify --fix` quarantines orphan bodies instead of deleting them**: an orphan `cap/` file moves to `trash/<run>/cap/<dd>/<digest>` inside the root, under its own relative path. The report lists each move. `<run>` is a timestamp, the pid, and a random suffix, created exclusively. The move is a hard link plus an unlink, so no run ever replaces another run's evidence. Just before each move the sidecars are re-read, and a body one names by then is skipped. A body named after its move is a `missingBody` finding with its quarantine path. `--fix` assumes no concurrent writer, and the store has no write lock. A later run inventories `trash/` and never scans it as live content. `--restore <run>` moves a run's bodies back, and skips any body whose live path is occupied. `--empty-trash` runs after the verify report, keeps a body that a current sidecar names and this command's own moves, and deletes the rest. It is the only action that deletes a body file. `trash/` carries a `.fsck-quarantine` marker. A `trash/` without it, or a symlinked one, is `foreignRoot` and is left alone. Stale `tmp/` files are still deleted. (#15)
- **The bucket verify engine moved out of the serving core**: import `@autocache/waybackify-verify` (or its `/retry` and `/verify-checkpoint` subpaths) in place of `@autocache/waybackify-serve/parity` and `/retry`. The serving core no longer exports them and no longer depends on `undici`, so the Node-only verifier stays off the edge graph. (#16)

### 🐛 Fixed
- **The GitHub probe trusts a graft only inside the renamed repo**: a grafted deep link that redirects to a GitHub route such as `/login` or to another repo is inconclusive. The caller defers the link. Before, a login page that answered 200 counted as a rename. A redirect to the renamed repo's root is followed, and the root's own answer settles the graft. A redirect to `github.com` on a port other than the default is off GitHub, the same rule the deep-link parser applies. (#17)
- **A GitHub route is not a deep link**: `githubRepo` returns null for a first path segment that names a GitHub route (`/orgs/...`, `/login/...`, `/settings/...`). It also rejects an owner or repo outside GitHub naming, and an owner may carry the underscore of an Enterprise Managed User. The repo root with only a query or a fragment is the home page, not a deep link. A path a fetch can move is not a deep link either. That means a backslash, a tab, or a line break in the text, or a segment that decodes to `.` or `..`. A raw space or accented letter is only percent-encoded, so such a link is still probed. A fetch of such a text requests another path, so the probe never fires for it. (#17)
